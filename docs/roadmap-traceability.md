# SafeOS Roadmap Traceability

Audit baseline: 2026-11-01. The roadmap is the pasted SafeOS product roadmap supplied by the project owner. Its color/status marks are preserved as source context, not treated as evidence that software works. No repository test suite was found during this audit.

## Implementation plan

1. Establish a safe, reproducible Debian live-build path on the external volume and verify image contents.
2. Provide an actual install path, first-run local account setup, working launchers for applications that exist, and a recovery path; test in disposable virtual machines.
3. Implement and test only local, transparent, consent-based functionality supported by the repository. Keep cloud/provider-dependent features blocked until their services, credentials, protocols, and data-retention decisions exist.
4. Remove or disable deceptive placeholders, hidden collection, and claims that imply protections or integrations that are not implemented. Run source, image, and VM acceptance checks before marking roadmap rows complete.

## Decisions and external blockers

- Confirm whether the supported release target is Debian Bookworm on x86_64 PCs only; the current image configuration says `amd64`, but the product roadmap also names Chromebook and custom hardware.
- Define whether installation may erase a disk, what recovery/rollback guarantee is required, and whether Secure Boot is in scope. No destructive install behavior will be assumed.
- Supply SafeCloud/SafeStore/SafeAI/HouseLearning endpoints, test credentials, authentication and authorization contracts, signing-key ownership, data retention, and offline behavior before those integrations are implemented.
- Identify redistributable packages and licensing decisions for SafeSuite, Office/Google, `.exe`, macOS/Windows subsystems, and commercial app-store features.
- Define JiraffeScript's command grammar and privilege model, and Krow's supported diagnostic/repair actions.
- Confirm any future consent-based remote-support use case separately. Broad screen viewing, takeover, hidden monitoring, punitive lockout, and exam surveillance remain excluded.

## Audit evidence

- `README.md` describes a Debian/XFCE image and modular scaffolds; it does not define an installer or supported-hardware matrix.
- Initial audit evidence: `scripts/prepare_live_build.sh` disabled Debian Installer, installed a basic desktop, and did not package application/system modules as working applications. Current changes enable the installer and integrate only tested local package-backed launchers.
- `scripts/validate_safeos.sh` verifies directories, selected files, shell syntax, and ISO/checksum existence only.
- Initial audit evidence: `scripts/build_iso.sh` used `/tmp` by default and moved its artifact into the repository's `iso/` directory. Current changes use path-guarded external-volume storage and content-addressed release names.
- `docs/security-model.md`, `docs/installer-flow.md`, `docs/package-manager-design.md`, and `docs/driver-management.md` describe intended features but exceed current implementation evidence.
- The build host has `docker` and `qemu-system-x86_64`; `lb` and `xorriso` are absent. The external volume has available capacity. Docker cannot currently connect to its configured daemon, so a Linux build environment is not yet available.
- The previously untracked `docs/SAFEOS_COMPLETION_PROMPT.md` was present before this work and remains untouched.
