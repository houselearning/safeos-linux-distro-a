# SafeOS architecture and implementation status

## Goals
SafeOS currently builds a Debian Bookworm amd64 live/install image with XFCE. Its architecture is Debian live-build plus a small allowlisted set of C launch wrappers around packaged desktop applications.

## Core layers
1. **Boot and installer**
   - Debian live-boot/live-config
   - GRUB BIOS and EFI entries generated by live-build
   - Debian Installer live mode; no custom hardware diagnostics
2. **Desktop environment**
   - XFCE with package-provided panel, session, and settings tools
   - Desktop entries invoke compiled allowlisted wrappers
3. **Application launchers**
   - Firefox ESR, Thunar, Galculator, LibreOffice, Parole, Cheese, XFCE settings/terminal, and Geany
   - A wrapper returns a clear unsupported status for unmapped products
4. **Local utilities**
   - Desktop notifications through `notify-send`
   - `safeos-update` uses signed Debian APT metadata only after an explicit user command
   - `safeos-settings` stores a small allowlist of user-local preferences; it does not edit sectors or system policy
5. **Unavailable integrations**
   - Cloud, AI, app-store, scanner, remote-management, and custom-driver interfaces are not connected to services
   - No telemetry or student monitoring starts in the desktop session

## Modular design
App source wrappers use `apps/common/`; the allowlist is the source of truth for launchable commands. A directory or README does not imply a feature is integrated.

## Performance focus
- XFCE package set
- No custom background collection services
- Hardware-specific driver behavior is inherited from Debian and has not been validated on target devices
